# compliance-backend

Deflow's recommendations and Payment Passport service, configuration (b): recommendations plus evidence pack, no contracts. One instance per processor (single tenant). The design is in `openspec/changes/archive/*-design-compliance-backend/design.md`; this slice is `openspec/changes/add-compliance-backend/`.

What it does, per deposit to one of the processor's addresses:

1. **Ingest.** eventscale delivers the `Transfer` within seconds (`seen`). The `eth_getLogs` reconciler confirms it at depth N (`confirmed`), or marks it `orphaned` if it is not on the canonical chain.
2. **Check.** KYT (GoPlus, demo only), sanctions (exact address match against versioned list files), structuring (`SPLIT-03`) and the issuer blacklist (`isBlacklisted` at the payment block). A failed or timed-out check is `UNAVAILABLE`, which the ruleset maps to HOLD.
3. **Recommend.** The rule engine runs the MLRO-approved ruleset that is effective at the payment's block time.
4. **Decide.** An `auto` CREDIT or HOLD is signed by the processor's policy key. Anything else opens an officer case, and the officer signs in their own wallet. Decisions are EIP-712 `Decision` structs, identical to what `ProcessorHub` accepts.
5. **Passport.** Each decision issues a pack version (`deflow-evidence/1.0`) with salted roots, a detached ES256 JWS and a journal hash chain. Projections per recipient profile verify with `docs/evidence-pack/verify_pack.py`.

## Run locally

```sh
cd compliance-backend
docker compose up -d                      # Postgres 17, anvil, eventscale (+ NATS on 4222)

mkdir -p keys
cast wallet new --json | jq -r '.[0].private_key' > keys/policy.hex
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out keys/evidence.pem

cp config.example.json config.json        # edit officers, mlro, deposit addresses
go run ./cmd/compliance-backend serve -c config.json
curl -s localhost:8080/healthz
```

Then import and approve a ruleset. The MLRO signs the returned `approval_typed_data` with any EIP-712 wallet, or with `cast wallet sign --data`:

```sh
curl -s -X POST 'localhost:8080/v1/rulesets?effective_from=2026-01-01T00:00:00Z' \
  -H 'Authorization: Bearer change-me' --data-binary @rulesets/2026.10-1.json > import.json
jq .approval_typed_data import.json > approval.json
SIG=$(cast wallet sign --private-key $MLRO_KEY --data --from-file approval.json)
curl -s -X POST localhost:8080/v1/rulesets/2026.10-1/approve -H 'Authorization: Bearer change-me' \
  -d "{\"effective_from\":\"2026-01-01T00:00:00Z\",\"signature\":\"$SIG\"}"
```

Other commands:

```sh
go run ./cmd/compliance-backend backfill -c config.json -chain 84532 -from-block 123456  # retro: packs get reconstruction=true
go run ./cmd/compliance-backend ruleset-hash rulesets/2026.10-1.json                    # version and ruleset_hash
kill -HUP <pid>                                                                         # reload sanctions lists
```

## Configuration

`config.example.json` lists every field. Unknown fields are rejected.

| Field | Meaning |
|---|---|
| `database_url`, `listen`, `api_token`, `data_dir` | Postgres, HTTP address, API bearer token, where raw provider responses are kept (`data_dir/raw/<sha256>`) |
| `nats_url` | eventscale's NATS. Empty disables the hint, and the reconciler alone still records everything |
| `processor` | legal name, LEI, CASP id, NCA, RFI channel, certificate URL; printed in every pack |
| `chains[]` | `chain_id`, `rpc`, `confirmations` (N), `reconcile_interval`, `chunk`, `eventscale_network`, `tokens[]` (address, decimals, `eventscale_alias`, `eur_rate`, `fx_source`), `deposit_addresses[]` (address, `merchant_id`) |
| `keys` | `policy_key_file` (hex secp256k1, signs automatic decisions), `evidence_key_file` (PEM P-256, signs packs), `evidence_kid` |
| `officers[]` | `address`, pseudonymous `officer_id`, `mask` (CREDIT=1 HOLD=2 FREEZE=4 RETURN=8, as in `ProcessorHub`) |
| `mlro[]` | addresses allowed to approve rulesets |
| `sanctions_lists[]` | `name`, `version`, `path` (one address per line, `#` comments) |
| `kyt.goplus_base_url`, `check_timeout`, `decision_ttl`, `worker_interval`, `retention_years` | |

## API

All endpoints except `/healthz` need `Authorization: Bearer <api_token>`. Errors are `{error, detail}` with status 400, 401, 403 (signature from an unauthorised key), 404 or 409 (forbidden transition or stale request).

| Method and path | Purpose |
|---|---|
| `GET /healthz` | DB status, reconciler lag per chain, hint `ok`, `degraded` or `disabled` |
| `GET /v1/cases` | payments waiting for an officer, with recommendation and reasons |
| `GET /v1/payments/{ref}` | payment, check results, recommendation, decisions, pack versions (`ref` is the 0x paymentId) |
| `GET /v1/payments/{ref}/typed-data?decision=FREEZE` | EIP-712 typed data for the officer to sign; valid for 15 minutes |
| `POST /v1/payments/{ref}/decisions` | `{decision, signature, rationale}` returns `{pack_id, pack_version}` |
| `POST /v1/rulesets?effective_from=RFC3339` | ruleset JSON body; returns `ruleset_hash` and the approval typed data |
| `POST /v1/rulesets/{version}/approve` | `{effective_from, signature}` by an MLRO; the ruleset is immutable from then on |
| `POST /v1/packs/{pack_id}/projections` | `{profile, prepared_for, purpose}` returns the canonical projection JSON; every issue is logged |

Profiles: `MASTER`, `FIU_SUPERVISOR` (nothing withheld), `AUDITOR`, `OFF_RAMP`, `BANK`.
